### 两处「示意图该不该报错」

- **填到一半/填错时不弹窗、不崩**：该项回落默认值，图右上角用红框标出

  「没给值、用默认、不算错误」，于是**填错了反而没有任何提示** —— 改成原样传那段文本。
- **井落在计算域外**（`well_pos` 不在 `xr`/`zr` 内）：**仍把井画出来**（坐标轴扩到包住它），
  并在图上显著标「井在计算域之外」。这是真正的配置错误 —— 之前井会直接画到画面外，
  用户看不到任何东西、也查不出原因。

## 2026-11-04 — `solve()` 拒绝把结果写进 zmlx 包目录

一次求解会写出成百上千个 `.seepage` / `.txt` 快照，落进源码目录既污染发布内容、
也容易被误提交。所以：

- **新增 `_is_inside_package(path)`**：判断路径是否落在 zmlx 包目录内（含包目录本身）。
  用 `os.path.realpath` + `commonpath` + `normcase` 比较，而不是字符串
  `startswith` —— 后者会把带 `..` 的等价路径、以及同名前缀目录（`zmlx_evil`）判错；
  `realpath` 还会解析符号链接，指向包内的软链接同样被拦住。
- **`solve(..., folder=...)`**：若 `folder` 在包内，**强制改为 `None`**（不保存），
  并发出 `warn` 提示 —— 不静默改写。「用户以为在保存、实际没保存」是最难查的那类问题。
- 包外路径照常保存，行为不变。

验证：包目录本身、`scen/geothermal`、其子目录、含 `..` 的等价路径均判为「包内」；
父目录、同前缀目录 `zmlx_evil`、`D:/out` 判为「包外」。把 `folder` 指向包内时，
转发给 `tfc.solve` 的是 `None`、目录**没有被创建**、且产生 1 条告警；
指向包外时正常生成 `models/*.seepage` 与 `cells/*.txt`、无告警。

## 2026-11-04 — 参数界面记住上次输入；单位改显示在输入框内

### 记住参数

- **存到 `app_data.temp('geothermal_widget.json')`**：每次改动后自动写盘，
  下次打开控件时读回来填上 —— 不用重新输入。
- **存的是各框的原始文本**，不是解析后的数值：某个框一时填得不合法也原样保留，
  下次打开还在，不会因为「解析失败」被悄悄清掉。
- **防抖 400 ms**（单次 `QTimer`）：输入路径时逐字符触发 `textChanged`，
  不防抖就是每敲一键写一次盘。「清空（全部用默认）」按钮则**立即**写盘。
- **结果保存目录的特例**：状态里另记一项「保存时的工作目录」。恢复时若发现
  存下的目录等于**当时**的默认值，就改用**当前** `os.getcwd()` ——
  于是换过工作目录后默认目录会跟着变，而手动填过的自定义路径仍原样记住。
- **放 `app_data.temp` 而非当前工作目录**：这是界面偏好，不该在用户项目目录里留文件
  （`quick_look` 的控件存在 `os.getcwd()`，那是它的选择；本包按自己的习惯放缓存目录）。

### 单位显示

- **单位不再写进标签**，改为输入框**内部右侧的只读后缀**（`QLineEdit.addAction`
  放一个置灰的 `QAction`）：标签那一列因此能对齐，框里又能直接看到单位，
  而且 `text()` 里仍只有数值，不会把单位混进要解析的字符串。
- 表单定义从 4 元组扩为 5 元组 `(参数名, 标签, 单位, 提示, 解析器)`；
  无量纲项（网格数、孔隙度）单位留空、不加后缀。求解时长的单位「年」同样走这条路径。

验证：12 个参数的单位后缀逐项正确（`m` / `kg/m³` / `J/(kg·K)` / `W/(m·K)` / `m²` / `s`，
网格数与孔隙度无后缀）；填值后 `text()` 仍是纯数值、`_collect()` 结果不变；
重开控件后参数正确恢复且单位后缀仍在；端到端求解与结果保存正常。

## 2026-11-04 — `update_power` 改用 `repr` 存储时间与能量，保证无损

原来用 `f"{t1:.10f}"` / `f"{e1:.10f}"` 存进 `well_t` / `well_e`，是**定点**格式，
只保留小数点后 10 位，精度会丢：

- 很小的数被直接抹平：`1.2345678901234567e-12` → `'0.0000000000'`，读回成 `0.0`
  （相对误差 100%），下一轮的 `power = (e1-e0)/(t1-t0)` 就完全失真；
- 超过 10 位小数的数被截断：`3.141592653589793` → `'3.1415926536'`。

现改为 `repr(t1)` / `repr(e1)`：

- `repr` 是 Python 保证「`float(s)` 逐位等于原值」的**最短**表示，往返无损；
- 比 `f"{x:.17g}"` 更干净 —— 后者会把 `3.141592653589793` 写成
  `'3.1415926535897931'`（多出无意义的尾数）；
- 实测 `432000000.0`、`1.2e-12`、`1.2e15`、`0.0`、`1e308`、`5e-324` 等均无损往返。

⚠️ 顺带记录一个已知边界（未改）：`t1 == t0` 时 `power` 会抛 `ZeroDivisionError`。

## 2026-11-04 — `get_average_area`：总长为 0 时改抛 `ValueError`

- **原行为**：两段长度都为 0 时 `dl / dp` 是 `0/0`，抛 `ZeroDivisionError`；
  这个异常既不说明哪一步出的问题，也和函数其它参数校验（`l1` / `l2` 为负抛
  `ValueError`）不是同一类，调用方难以统一处理。
- **现行为**：显式判断总长，`l1 + l2 == 0` 时抛
  `ValueError: 两段长度之和必须大于 0，当前 l1=…, l2=…`，
  与「长度为负」统一成同一类错误（都是「参数无法确定等效面积」）。
- **检查顺序不变**：仍是「先判面积 → 再判长度 → 最后判总长」，
  因此面积 `<= 0` 时直接返回 `0.0`，不会因为长度有问题而报错。
- 文档同步更新 Raises 一节与 Example（补了总长为 0 的调用示例）；

  原有正常结果（0.181818… / 2.0 / 3.4482758… / 0.0）全部不变。

## 2026-11-04 — 补全 `get_average_area` 的文档

说明书里原来只有一句 `dp = dL / s`，参数与返回值全空。现补全：

- **讲清它算什么**：两段**串联**通道的阻力等效面积
  `(l1 + l2) / (l1/s1 + l2/s2)`，即以长度为权的**调和平均**；
  阻力是 `1/s` 的线性叠加，所以小面积那一段占比更重。
- **与 `equivalent_area` 对照**：一个是「两段常量面积」，一个是「一段连续线性变截面」，
  两者数值**不相等也不该互相替代**（`(0.1,1,1.0,1)` 得 0.1818，
  而 `equivalent_area(0.1, 1.0)` 得 0.3909）。
- **补齐退化与异常**：面积 `<= 0` 返回 `0.0`（且**不检查**长度）；
  `l2 == 0` 等于 `s1`；长度 `< 0` 抛 `ValueError`。
- **记录一处已知边界**：两段长度都为 0 时 `dl / dp` 为 `0/0`，抛 `ZeroDivisionError`，
  函数未额外拦截（此时等效面积本就没有定义），调用方需自行保证 `l1 + l2 > 0`。
- 文档里的示例值与全部断言均经实测核对。
